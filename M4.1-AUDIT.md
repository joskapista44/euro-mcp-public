# M4.1 reuse audit

M4.1 started with a mandatory inventory of the current main branch before adding a second formatting implementation.

## Finding

The requested write surface already exists from the merged M2 work (`live-formatting.cjs`, PR #8):

- bold / italic
- font name / size / color
- fill color
- horizontal / vertical alignment
- wrap
- borders
- number format
- live ONLYOFFICE spreadsheeteditor/callCommand execution

Therefore M4.1 does **not** introduce a parallel formatter. It hardens the existing formatter with the missing acceptance layer: structured same-session live verification.

## Verification policy

After applying each requested format field, the command reads the same `ApiRange` while the editor session is still open.

- PASS: live value equals requested value.
- FAIL: live value is measurable and differs from requested value.
- UNKNOWN: the live API does not expose a reliable getter/property for the requested field.

A measurable mismatch makes the formatting result fail. Unsupported readback never gets guessed into PASS.

### Reliably readable in M4.1

- bold
- italic
- font name
- font size
- font color when the live property returns an `ApiColor`
- fill color via `GetFillColor`
- horizontal alignment
- vertical alignment
- wrap via `GetWrapText`
- number format via `GetNumberFormat`

### Explicit UNKNOWN

`ApiRange.SetBorders` exists, but the spreadsheet ApiRange documentation exposes no corresponding live border getter. Border write remains supported, while its structured verification is `unknown` instead of a fabricated success.

## Architecture

No DocBuilder, downloaded XLSX, ZIP/XML/OOXML, WebDAV or persisted-file readback is introduced. The write and verification happen inside the same live editor command/session.
